# Skoot Conversation Privacy and Access Policy

## Scope

The first Skoot conversation release is a **private, text-only execution companion**. Each conversation belongs to exactly one authenticated Skootly user. The product stores no coach, team, or client-sharing relationship in this release; therefore no other user can list, read, write, export, or delete another person’s conversation.

| Topic | Current product rule |
| --- | --- |
| Consent | A user must explicitly start a private conversation before any message is stored. |
| Context | Skoot receives only the owner’s current active Skoots and enabled user-supplied learning context. |
| External systems | Skoot does not inspect, browse, upload to, post to, message, or alter any external platform. |
| Retention | Messages remain private until the owner permanently deletes the conversation. |
| Deletion | Deleting the conversation permanently cascades to its messages. |
| Export | A future export route must return only the authenticated owner’s own conversation and message records. |
| Voice | Voice upload and transcription are deliberately out of scope until separate consent, transcription, retention, and deletion controls are approved. |

## Guardrails

Skoot is not a general-purpose client-data chatbot. It is bounded to focused execution: it may clarify a goal, point to the owner’s active Skoots, reference authorized imported learning material, and suggest one or two user-confirmed next moves. It must never represent that it has verified external state or completed an external task.

## Future coach or team access

No coach or team role can access conversation data until Skootly implements explicit client-to-coach sharing records, per-conversation consent, least-privilege scopes, revocation, audit history, and tests for cross-client denial. A future feature must be opt-in rather than inferred from a workspace membership.
